# 发布计划

- 状态：阶段性路线图，不承诺具体商店日期
- 最后更新：2026-07-19

## 1. 发布原则

每个版本必须有冻结范围、不可变规则/内容版本、可回滚构建、迁移验证、实际测试证据和已知问题。传统规则/内容未核验时宁可缩小功能，不用伪数据补齐页面。

## 2. 阶段 0：项目准备（已完成基线）

交付：PRD/规格/数据/架构/测试/发布文档；Expo SDK 57 严格 TypeScript 工程；Expo Router 最小页；Development Build 配置；分层目录；Zod 数据门禁；Vitest/ESLint/Prettier/CI；`AGENTS.md`。

退出条件：`pnpm install --frozen-lockfile`、`pnpm run check`、Expo 配置检查和基础启动验证通过；生产数据为空且缺失清晰；无密钥；无专业算法。

## 3. V1：离线基础闭环

建议增量：

1. 起卦核心（模块二已实现）：领域模型、随机端口、三枚铜钱、会话撤销/恢复/锁定及测试；SQLite 跨进程持久化仍归后续数据库增量；
2. 卦象核心（算法已实现、生产数据待审核）：八卦位型、显式 64 卦映射契约、动爻/变卦和 4096 穷举；完整映射导入仍受来源门禁约束；
3. 内容数据库：来源确认、细分 Schema、导入工具、SQLite migration 和完整性测试；
4. 基础解卦：版本化规则 Schema、结构化结果、本地模板和依据；
5. App 页面：完整起卦、结果、历史、知识、设置；
6. 隐私、风险、无障碍、性能与离线验收。

V1 发布门禁：

- 相同输入/版本结果一致；
- 所有内容可追溯且授权可发布；
- 4096 状态、迁移升级、恢复/锁定测试通过；
- Android/iOS 目标设备完成离线闭环；
- 风险与隐私文案经过产品/法律适当审核；
- 没有未披露的高严重度缺陷。

## 4. V2：专业六爻与设备能力

前置：负责人明确采用规则体系，并提供可定位来源、授权、规则版本和固定案例。

交付：八宫、世应、纳甲、六亲、六神、干支、月建日辰、旬空、生克冲合、旺衰、用神、动变；专业排盘页；加速度摇动、冷却、触觉与动画。

门禁：规则交叉评审；完整排盘固定案例；历法支持范围和时区边界；传感器不影响概率；前后台订阅清理；Android/iOS 真机矩阵。专业规则缺一项来源不得用模型生成补齐。

## 5. V3：AI 表达与正式发布完善

交付：可选 AI 白话、Schema 防越权、本地回退；崩溃/错误治理；隐私政策、用户协议、风险声明；无障碍和性能优化；商店构建与发布物料。

门禁：默认离线能力完整；AI 明示并可关闭；无密钥进客户端；提示注入/越权/高风险输出测试；数据传输获同意；商店合规与签名由所有者确认。

## 6. 构建渠道

- **development**：含 dev client，内部开发设备；
- **development-simulator**：iOS Simulator（需 macOS/EAS）；
- **preview**：不含开发工具的内部验收；
- **production**：商店候选。

`eas.json` 只定义 profile。首次远程构建前由所有者登录 Expo、确定项目 ID、Android package、iOS bundle identifier 和签名策略。Codex 不自动触发构建或提交凭据。

## 7. 版本策略

- 应用版本遵循 SemVer 语义；
- `inputSchemaVersion`、`rulesetVersion`、`contentVersion` 和数据库 migration 版本分别管理；
- 规则/内容改变结果时必须升对应版本；
- 旧历史保留原快照，新规则以独立对比结果存在；
- 已发布 migration、规则包和内容包不可原地修改。

## 8. 发布检查表

- 范围、PRD 和 ADR 更新；
- frozen lockfile 安装及依赖安全复核；
- `pnpm run check` 和 CI 通过；
- Expo Doctor/配置解析通过；
- 数据 Schema、来源、授权、哈希和完整性通过；
- migration 从受支持版本升级通过；
- Android/iOS 开发与预览构建真机通过；
- 离线、恢复、删除、无障碍、性能通过；
- 隐私/协议/风险文案和商店资料确认；
- 回滚策略、已知问题和支持渠道明确。

## 9. 当前未解决的发布前置

- 正式产品名称、图标和 bundle/package identifier；
- 经核验、可发布的《周易》底本与现代解释授权；
- 专业六爻采用体系与案例；
- 目标支持 OS/设备矩阵；
- Expo/EAS 项目所有者与签名策略；
- 隐私政策/用户协议的责任审核人；
- 分析、崩溃监控和 AI 服务是否启用及其数据合规方案。
