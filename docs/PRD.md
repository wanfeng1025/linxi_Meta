# 产品需求文档（PRD）

- 文档状态：模块一基线
- 产品阶段：V1 规划
- 最后更新：2026-07-19
- 适用规则版本：尚未发布；首个正式版本待后续模块定义

## 1. 产品定位

本产品是一款离线优先、过程透明、规则可追溯的“六爻起卦与解卦 App”。它帮助用户完成三枚铜钱起卦、查看本卦/变卦与经核验的《周易》文本，并保存可复现的历史记录。

产品必须区分三层能力：

1. **简易《周易》模式**：展示卦象、动爻、经核验的卦辞爻辞与基础分类解释；
2. **专业六爻模式**：按已选定且有来源的规则体系完成纳甲排盘与结构化分析；
3. **文本表达层**：模板或 AI 将结构化事实改写为白话，不参与计算。

三层可以在同一结果流程中组合，但不得混成随机生成断语的系统。本产品是文化学习和个人反思工具，不承诺预测准确性，不替代医疗、法律、财务或其他专业意见。

## 2. 目标用户

- 希望用三枚铜钱完成基础起卦并理解卦象的普通用户；
- 学习《周易》、需要对照卦辞爻辞和变卦关系的用户；
- 在规则来源明确后，需要查看专业六爻排盘事实的进阶用户；
- 重视离线、隐私、历史可复现和规则依据的用户。

## 3. 核心使用场景

- 用户围绕一个非高风险问题记录背景，离线完成六次起爻；
- 用户中断起卦后恢复，确认六爻原始铜钱未丢失、顺序未变化；
- 用户查看本卦、动爻、变卦及相应的已核验文本；
- 用户按事业、关系、学习、出行等分类查看基础解释，同时看到判断依据；
- 用户在历史中回看当时的原始输入、规则版本与结果快照；
- 进阶用户在后续版本切换到专业模式，查看可追溯排盘而不是不透明断语。

## 4. 模式定义

### 4.1 简易模式

面向 V1。只使用三枚铜钱起卦、本卦/变卦关系、经核验的卦辞爻辞和版本化基础解释规则。页面隐藏未实现的专业字段，不用空值假装已排盘。

### 4.2 专业模式

面向 V2。在规则体系、来源、版本和固定案例完成评审后，提供八宫、世应、纳甲、六亲、六神、干支、月建日辰、旬空、生克冲合、旺衰、用神与动变分析。不同流派不得无提示混用。

### 4.3 文本表达

V1 使用本地确定性模板。V3 可选 AI 白话，但输入只包含允许改写的结构化字段，输出经 Schema 校验并可回退到本地模板。AI 不产生或修改卦象与核心判断。

## 5. 版本范围

### V1：离线基础闭环

- 问题/背景可选输入与风险提示；
- 点击触发三枚铜钱、连续六次起爻；
- 起卦进度、撤销/恢复/锁定；
- 本卦、动爻、变卦；
- 经来源核验的卦辞、爻辞；
- 版本化的基础分类解释与判断依据；
- 本地 SQLite 历史记录、详情回看、删除确认；
- 离线完成全部核心流程；
- 设置中的规则/内容版本、隐私和风险声明。

### V2：专业六爻与设备体验

- 明确规则体系后的专业六爻纳甲排盘；
- 干支日历、月建日辰与完整结构化分析；
- 摇动触发、加速度传感器管理、冷却与触觉反馈；
- 铜钱动画与专业排盘页；
- 完整真机固定案例验收。

### V3：可选智能表达与发布完善

- AI 白话、摘要、术语解释及本地回退；
- AI 输出校验、隐私同意与网络状态提示；
- 无障碍、性能、崩溃监控与发布治理；
- Android/iOS 正式构建、商店物料与发布验收。

## 6. 明确不做

- V1 不实现八宫、世应、纳甲、旺衰、取用神等专业规则；
- 不生成无可靠来源的 64 卦、384 爻辞或古籍注释；
- 不把四种爻值等概率抽取，不用摇动力度影响结果；
- 不提供“必然应验”、实时大师咨询、社交排行榜或博彩功能；
- 不把 AI 当作起卦随机源、排盘引擎或吉凶裁决者；
- 不提供医疗诊断、投资保证、法律结论或危机干预替代；
- 模块一不实现完整业务页面、正式数据库 migration 或专业算法。

## 7. V1 页面清单

1. 首页：产品边界、开始起卦、最近历史；
2. 问题输入页：可选分类和背景、隐私/风险提示；
3. 点击起卦页：六次进度、三枚铜钱原值、撤销、恢复与锁定；
4. 结果概要页：本卦、动爻、变卦和主结论入口；
5. 详细解卦页：结构化结论、文本、分类解释与依据；
6. 历史记录页：按时间查看本地记录；
7. 历史详情页：原始输入、规则/内容版本和结果快照；
8. 知识页：术语、方法和经核验来源说明；
9. 设置页：显示、数据管理、版本、隐私与风险声明。

专业排盘页在 V2 启用；V1 不用伪数据占位。

## 8. 用户起卦流程

1. 用户进入首页，阅读“文化参考、非专业建议”提示；
2. 可选输入问题背景和分类；问题原文默认只保存在本机；
3. 系统创建草稿会话，记录会话 ID、创建时间和 `rulesetVersion`；
4. 用户点击按钮六次，每次生成三枚独立铜钱并立即保存原值；
5. 第一次结果写入初爻，依次至第六次上爻；
6. 锁定前可按明确交互撤销/恢复，所有状态转换可测试；
7. 第六爻完成后用户确认并锁定原始记录；锁定后不得改写；
8. 领域层确定本卦、动爻和变卦；
9. 内容层按版本读取已核验文本，解释层输出结构化结果与依据；
10. 应用将结果快照写入历史，随后展示概要和详情。

## 9. 离线能力

- V1 起卦、卦象计算、内容读取、基础解释和历史管理必须离线可用；
- 首次安装应包含经核验的版本化内容，不依赖启动时下载；
- 网络中断不得改变或丢失已产生的铜钱结果；
- AI 功能即使在 V3 启用也必须显式可选，离线时回退本地模板；
- 所有时间、随机源与保存失败都以明确错误状态处理，不静默重试生成新结果。

## 10. 历史记录

每条历史至少保存：记录 ID、可选问题/分类、创建/完成时间、六次三枚铜钱原值、初爻到上爻顺序、本卦/变卦标识、动爻、`rulesetVersion`、`contentVersion`、结构化解释快照和 Schema 版本。

默认只存本机。规则或内容升级不得覆盖旧记录；回看先展示原快照，并可在用户明确操作下使用新版规则生成独立对比结果。删除必须确认并实际清除关联本地数据。

## 11. 风险与提示

- 传统规则存在流派差异，专业能力上线前必须明确体系和来源；
- 古籍版本、版权和校勘状态可能不一致，内容需逐条记录版本与授权；
- 用户可能把结果用于高风险决策，关键页面须提示“仅供文化学习与个人反思”；
- 问题文本可能含敏感信息，默认离线、最小收集，不写日志；
- 设备随机与恢复逻辑若设计错误会破坏信任，必须保存原值并做可复现测试；
- AI 可能幻觉或越权，必须字段白名单、Schema 校验、本地回退和安全提示；
- iOS 原生构建不能在 Windows 本地完成，需 macOS 或 EAS Build 验证。

## 12. 功能验收标准

### 模块一

- 依赖可由锁文件安装，基础页可由 Expo 启动；
- TypeScript 严格检查、Lint、格式、单元测试和数据校验通过；
- CI 只执行稳定自动化门禁，不声称覆盖真机；
- Development Build 有 `expo-dev-client` 与 `eas.json` 基础配置；
- 所有规定文档和 `AGENTS.md` 完整；
- 生产数据目录为空或只含来源完整且已核验的数据；当前不得含伪造内容；
- 仓库没有真实密钥和大规模业务实现。

### V1 产品

- 相同六次铜钱原值和相同规则版本得到逐字段一致的核心结果；
- 四种爻值的生成来自三枚独立铜钱，不是四值等概率；
- 内部顺序始终初爻到上爻，展示倒序不改变数据；
- 无网络时可完成起卦、查看内容并保存/回看历史；
- 所有展示文本能追溯到 `sourceId`、内容版本或规则编号；
- 中断恢复后不重复生成已完成爻；锁定后原始记录不可修改；
- 数据库升级保留历史原始数据和结果快照；
- 高风险提示、隐私说明与数据删除入口可访问。
