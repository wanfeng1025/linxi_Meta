# 卦象核心规格

- 状态：确定性算法、生产 64 卦显式映射与 4096 次全映射验收已实现
- 编码版本：`yin-zero-yang-one-bottom-up-v1`
- 最后更新：2026-07-20

## 1. 适用边界

本模块只负责阴阳位、八卦位型、上下卦、本卦、动爻、变卦和显式 64 卦映射。它不实现 SQLite 导入、卦辞爻辞、八宫、世应、纳甲、六亲、六神、旺衰、用神或解卦。

编码/变爻是已冻结的确定性规则；传统名称、符号、文王卦序和上下卦映射属于版本化文化数据。二者不得混为一张靠程序下标推断的表。

## 2. 统一编码

- 阴为 `0`，阳为 `1`；
- 所有三位和六位数组均从初爻向上；
- 三位码的第一个字符对应该三爻卦的最下爻；
- 六位码的第一个字符对应初爻，第六个字符对应上爻；
- 下卦取位置 1、2、3，上卦取位置 4、5、6；
- 编码只描述位型，不代表文王卦序；禁止对六位二进制值加一得到卦序。

所有编解码、上下卦拆分和组合集中在 `src/domain/hexagram/encoding.ts`。UI 需要从上向下显示时只调用返回倒序副本的辅助函数，不改变领域数组。

## 3. 八卦位型与内容

`TrigramPattern` 是不依赖传统内容的技术位型，由唯一的三位码和 `trigram-pattern-{code}` 标识。八种位型始终可以双向编解码。

`TrigramDefinition` 是需要来源的数据记录，包含稳定 ID、名称、符号、三位码、三位阴阳、可空的五行/方位及数据版本。五行和方位仅为内容字段，不参与本模块计算。正式名称和符号只有在来源、授权和人工审核满足 `DATA_SOURCES.md` 后才能进入生产 catalog。

## 4. 显式 64 卦映射

每条 `HexagramDefinition` 显式保存：

- 稳定 ID；
- `kingWenSequence`（1 至 64）；
- 卦名；
- `upperTrigramId`；
- `lowerTrigramId`；
- 从初爻到上爻的六位阴阳和六位码；
- 不可变 `dataVersion`。

查询键由具名函数使用上卦 ID 与下卦 ID 生成，不使用 JSON 数组下标。catalog 解析器拒绝重复八卦 ID/位型/符号、重复卦 ID/文王序/六位码/上下卦组合、悬空八卦引用及位型不一致。

`HexagramCatalog` 带有仅能由 `createHexagramCatalog` 工厂返回的类型品牌，计算 API 不接受业务代码直接拼装的结构对象。运行时数据仍必须先经过 Schema 和 catalog 解析器，不能用 TypeScript 类型断言替代校验。

完整 catalog 还必须满足：八种三位码各一次、64 条记录、8×8 上下卦组合各一次、文王序 1 至 64 各一次。当前生产 catalog 使用不可变版本 `hexagram-mapping-2026-07-20-v1`，包含 8 条八卦和 64 条显式映射；完整性门禁必须成功，任何缺失、重复或版本漂移都应失败。

## 5. 本卦、动爻与变卦

输入必须恰好六条，数组索引与 `position` 同时为初爻到上爻：索引 0 的位置为 1，索引 5 的位置为 6。位置必须唯一并覆盖 1 至 6。

| 原始值 | 本卦位 | 是否动 | 变化位 |
| -----: | -----: | ------ | -----: |
|      6 |      0 | 是     |      1 |
|      7 |      1 | 否     |      1 |
|      8 |      0 | 否     |      0 |
|      9 |      1 | 是     |      0 |

动爻位置按 1 至 6 升序返回。无动爻时 `movingLines=[]` 且变化位与本卦位相同。结构推导不要求传统映射；完整计算必须通过传入的显式 catalog 同时解析本卦和变卦，缺少任何映射即报错。

## 6. 输出结构

结构结果包含原始位置/爻值、本卦六位、上下卦技术位型、动爻、变化六位、变化上下卦、编码版本和规则版本。catalog 解析成功后再增加本卦/变卦稳定记录及 `mappingDataVersion`。

该结果不含吉凶、趋势、行动建议或自由文本。相同原始输入、`rulesetVersion` 与 catalog 数据版本必须逐字段相同。

## 8. 自动化验收

- 八种三位码双向编解码且唯一；
- 上下卦拆分严格使用位置 1..3 与 4..6；
- 测试专用乾/坤夹具证明文王序不等于二进制序；
- 全静、全老阴、全老阳和阴阳交替边界通过；
- 穷举 `4^6 = 4096` 种原始状态，验证本卦位、变化位、动爻 0..6、位置唯一/升序、上下卦拆分、输入不变与重复计算一致；
- 穷举覆盖全部 64 种本卦位型和 64 种变卦位型；
- 使用 production catalog 穷举 4096 次本卦/变卦解析，验证全部映射成功、文王序范围合法、64 个本卦/变卦稳定 ID 全覆盖并且重复计算一致。

## 9. 发布就绪门禁与剩余数据

`verifiedCatalogSchema` 允许空数组，用于生产文化数据尚未获批时继续开发确定性算法和数据库结构。任何承诺展示正式卦名、文王卦序和本卦/变卦映射的构建，必须改用 `releaseReadyCatalogSchema`；该门禁拒绝空目录和只有非映射内容的目录，并继承完整八卦、64 卦、8×8 组合和文王序 1 至 64 的校验。

手动执行发布门禁：

```bash
pnpm exec tsx scripts/validate-hexagram-release.ts
```

发布门禁当前必须通过，并验证固定来源版本、八条正式八卦、64 条显式上下卦映射、简体名称规范、稳定 ID、审核角色/时间和不可变内容版本。后续修改任何记录必须提升 `contentVersion`，不得原地覆盖 `hexagram-mapping-2026-07-20-v1`。

该完成状态只覆盖八卦与 64 卦结构映射；384 爻辞、乾用九/坤用六原文、八宫、纳甲、六亲及解释文本仍不属于模块三生产数据。
