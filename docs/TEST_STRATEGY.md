# 测试策略

- 状态：模块四内容数据库基线
- 目标：用自动化证明确定性与数据边界，用真机流程覆盖无法稳定模拟的设备行为

## 1. 测试原则

- 测试验证规则，不迎合实现；不得跳过、弱化类型或硬编码输出通过门禁；
- 核心 domain 测试不加载 React Native、Expo Router 或 SQLite；
- 随机通过注入源测试，统计测试只发现实现偏差，不替代数学约束；
- 固定传统案例必须附规则集、来源和版本；未确认来源时不创建伪案例；
- 每次缺陷修复先增加能复现问题的最小测试；
- CI 结果只代表其实际运行范围。

## 2. 测试层级

### 2.1 单元测试

覆盖纯领域函数、值对象、状态机、Zod Schema、版本判断、模板组合和 Repository 映射。运行快、无网络、无设备、无真实数据库（映射测试除外）。

### 2.2 属性与穷举测试

- 铜钱：每次恰三项且每项 2/3，合计与爻状态一致；
- 会话：追加/撤销/恢复/锁定状态不变量；
- 卦象：穷举 4⁶ = 4096 种六爻值；
- 64 卦映射：来源数据导入后验证 8×8 组合唯一完整；
- 规则引擎：顺序无关输入、优先级稳定、冲突可解释；
- 相同输入 + 相同版本逐字段相等。

属性测试不得生成“预期吉凶”作为 oracle；期望来自规则不变量或已核验案例。

### 2.3 集成测试

- Application 用例 + 内存端口；
- SQLite migration、Repository 和事务（目标平台可用的测试环境）；
- JSON → Schema → SQLite 导入对账；
- 中断恢复与锁定幂等；
- 规则/内容升级后旧历史不变；
- AI 适配器的 Schema 拒绝、超时和本地回退（V3）。

### 2.4 组件/导航测试

聚焦状态到视图映射、错误/空态、无障碍标签、初爻/上爻展示顺序和路由参数校验。不得在组件测试重测领域算法。

### 2.5 E2E 与真机

真实 Android/iOS Development Build 验证：

- 连续六次起爻和前后台恢复；
- SQLite 持久化、升级与删除；
- 摇动阈值、去抖、冷却、订阅清理；
- 摇动力度不影响结果；
- 触觉、动画、屏幕尺寸和无障碍；
- 无网/弱网、本地时区、系统时间变化；
- 崩溃恢复不重复生成铜钱。

CI 不宣称覆盖上述设备行为。真机报告记录设备、OS、构建号、规则版本、步骤和证据。

## 3. 起卦核心测试矩阵（模块二已自动化）

- 合法 2/3 三元组的 8 种组合；
- 空、少/多于三枚、非法数字、非整数；
- 6/7/8/9 到阴阳/动静/变爻映射；
- 第一次初爻、第六次上爻；
- 第七次追加拒绝；
- 0/1/6 爻状态的撤销恢复边界；
- 未完整锁定、重复锁定、锁定后修改拒绝；
- 固定随机源的调用次数与结果；
- 序列化/恢复前后深度相等。

## 4. 4096 状态验收（模块三已自动化）

对每种 `[6|7|8|9]⁶`：

- 产生合法本卦位型和变卦位型；
- 结构穷举覆盖全部 64 种本卦位型和 64 种变卦位型；
- 显式映射得到存在的 1..64 传统编号（待完整 production catalog 来源确认后启用）；
- 动爻数量 0..6 且位置升序；
- 6 阴变阳、9 阳变阴、7 阳不变、8 阴不变；
- 上下卦拆分分别使用索引 0..2 和 3..5；
- 输入数组未被修改；
- 再次计算结果深度相等。

当前 4096 种结构状态已全部自动化。测试专用 catalog 只包含经网页明确交叉核对的八卦符号及乾/坤两条卦记录，用于证明显式解析和“二进制序不等于文王序”；不得据此声称完整 64 卦映射通过。catalog 校验器已经冻结 8×8 组合、文王序 1..64、ID/位型/组合唯一性门禁，完整生产数据导入后再增加 4096 次映射成功断言。

## 5. 数据测试

当前 `validate:data` 检查：

- 空 production catalog 合法；
- pending 结构示例符合通用 Schema；
- pending 记录不能进入 production catalog；
- verified 记录必须有审核、来源和授权信息。
- `data/source` production 数据先过 Zod、再过业务完整性；
- `data/draft` 独立统计且不会进入 production 导入；
- 输出内容数量、draft 数量、缺失来源、失败项与规范化 SHA-256；
- complete 模式要求 8 个八卦及 000..111 覆盖、64 个显式组合、384 个普通爻位、乾用九和坤用六；还要求八宫 64、纳甲 48、六亲 25、六神目录 6/日干起例 10、地支 12，并检查阶段世应、爻阴阳和多支引用。
- `schemas/` 的 18 份 Draft 2020-12 JSON Schema 具有稳定 `$id`，其中独立的 `professional-ruleset` Schema 描述单一版本规则包；`check:content-schemas` 阻止生成物与 Zod 源漂移。

当前真实 production 内容包括 72 条结构映射（8 八卦 + 64 卦）、一份独立已授权的古籍引文数据集（64 条卦辞 + 384 条普通爻辞）以及一份独立已授权的白话学习释义数据集（64 条卦辞解释 + 384 条普通爻辞解释）。两份文本数据集均校验固定原文件 SHA-256、64/384 覆盖、初爻到上爻位置、逐条内容哈希与不可变内容版本。白话释义只能作为学习参考，不能变成自动解卦规则。彖传、象传、特殊爻辞和专业规则仍为 0；专业完整数量测试使用明确 synthetic/test-only fixture，缺少真实数据时继续报告缺失，不能自动补全。

## 6. 数据库测试

已自动化空库升级、migration 004 升级到 005、重复启动、中途失败回滚、checksum 篡改检测、旧内容/历史数据保留、导入事务/幂等、导入报告、专业规则 Repository DTO 映射、六组三枚铜钱完整性、带版本比较链的追加式重新分析和数据库重开持久化。测试使用 Node 24 内置 SQLite 与合成 fixture；Expo Android/iOS 真机数据库、WAL 和升级仍需设备验证。

## 7. AI 安全测试（V3）

- 尝试修改本卦/变卦/动爻/主象被拒绝；
- 伪造 sourceId/ruleId 被拒绝；
- 未知字段、超长文本、危险承诺和提示注入被拒绝；
- 网络失败、超时、无密钥时本地回退；
- 不向服务发送未获同意的问题原文；
- AI 文本明确标识，不冒充古籍原文。

## 7.1 专业排盘测试（模块五安全骨架）

当前自动化覆盖生产规则包拒绝 test-only/混合版本、世应位置差、纳甲初爻到上爻顺序、六亲以宫五行为输入、六神从日干配置起排、六旬表读取、禁用关系不命中、历法输入/Provider 版本一致、用神上下文不足、动爻与飞伏结构和完整排盘版本字段。

这些期望来自 synthetic/test-only fixture，只能验证程序边界。64 卦八宫世应、48 纳甲、十日干、节气前/当/后、时区/DST、无动至全动、用神出现/不现、空破日冲等传统正确性测试仍等待双人确认的金标准文件；缺失期间不得把合成 fixture 改名或迁移为 production。

## 8. 覆盖率

模块一提供覆盖率命令但暂不设置任意全局阈值。为核心 domain 建立后，新增代码要求高分支覆盖并结合穷举/属性测试；覆盖率数字不能替代规则案例质量。阈值变更通过 ADR 决定，不得为过门禁下调。

## 9. 本地和 CI 命令

```bash
pnpm run typecheck
pnpm run lint
pnpm run format:check
pnpm run test
pnpm run test:watch
pnpm run test:coverage
pnpm run validate:data
pnpm run check
```

CI 使用 frozen lockfile，并运行 `typecheck → lint → format:check → test → validate:data`。原生构建、EAS 账号、模拟器和真机测试不放入基础 CI。

## 10. 发布证据

每个候选版本保存：CI 运行链接、依赖/锁文件变更、数据版本与校验结果、migration 升级结果、Android/iOS 真机矩阵、未解决缺陷、隐私/风险文案确认和签字人。未执行项目写“未执行/阻塞”，不得猜测通过。
