# 模块八：设备功能

## 边界

摇动只是 `castNext` 的触发方式。`ShakeDetector` 不生成硬币、不会读取或写入随机源，也不把强度、方向或传感器样本传给领域起卦算法。三枚铜钱仍由既有 `CastingService` 通过安全 `RandomSource` 独立生成和保存。

## 结构与生命周期

- `src/domain/device/ShakeDetector.ts` 是纯 TypeScript 状态机：`idle → candidate → shaking → triggered → cooldown`，并支持 `disabled`。
- `src/infrastructure/sensors` 提供 Expo 真机、Mock 与不支持三种适配器；页面不直接调用 Expo 传感器 API。
- `src/features/device/useShakeToCast.ts` 仅在页面 focus、应用前台、用户开启摇一摇且会话未完成时订阅；blur、后台、卸载、传感器不可用和第六爻完成都会移除订阅。
- 动画、进行中的起爻请求与冷却期间，传感器样本不会产生新的调用；同次有效摇动在被确认后进入 1200ms 冷却。
- 采样间隔为 50ms（20Hz），低于 Android 12 的 200Hz 限制，不申请高采样率权限。

## 默认阈值（`shake-detector-v1`）

| 配置         | 默认值 | 目的                  |
| ------------ | -----: | --------------------- |
| 候选阈值     |  0.55g | 忽略轻微桌面/手持噪声 |
| 峰值阈值     |  1.05g | 排除单次轻碰          |
| 最小样本     |      4 | 避免单个事件触发      |
| 最短时长     |  180ms | 确认为连续动作        |
| 最小方向变化 |      1 | 排除单向碰撞          |
| 静止样本     |      3 | 动作结束后才有效      |
| 冷却时间     | 1200ms | 防止连续重复起爻      |

阈值作为 `ShakeDetectorConfig` 集中注入；Android/iOS 真机校准后可新增平台配置，不修改随机或领域规则。

## 触觉与动画

- 触觉遵循“触觉反馈”和“减少触觉”设置；不支持时静默降级。
- 领域层先成功保存爻，再开始三枚铜钱翻转；动画结束只展示已保存的结果，不做二次随机。
- 系统“减少动态效果”或应用内“减弱”动画时跳过翻转；切后台会安全完成动画，解除操作锁。

## 诊断页

开发环境的“设置 → 设备诊断”显示可用性、权限、20Hz 采样、三轴值、强度、状态机、阈值、最近触发、订阅数和最近五条错误。生产构建不显示入口，直接访问也只显示非敏感禁用提示。
