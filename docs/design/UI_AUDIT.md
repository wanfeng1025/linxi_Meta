# 灵犀 Meta Web UI/UX 审计

> 审计基线：2026-09-18，分支 `codex/p0-production-readiness`。范围为 `apps/web`，不包含移动端 UI、领域算法和内容数据。

## Executive Summary

灵犀 Meta 已经具备可发布的匿名三币起卦闭环：随机源来自 Web Crypto，起卦由共享领域服务计算，六次起爻按初爻到上爻保存，结果从会话快照重新计算，JSON/PNG 导出和隐私边界已有测试，生产站点的核心路由可访问。现有视觉已经有墨绿、朱砂、玄黑、铜色和太极/卦象氛围，但页面仍以同一种 `card` 容器承载大多数信息，首页、知识页、方法页之间的层级差异不足；手机导航只是横向滚动导航；六十四卦目录是 64 条普通链接；起卦流程虽有铜钱和 GSAP，但缺少明确的准备、翻转、落定、完成状态。

本次重构目标是“现代东方编辑感”：墨绿为主、朱砂红为行动与风险信号、玄黑为底层墨色，暖纸/青铜为少量阅读与结构提示。动效只服务于可理解的状态变化，不改变任何业务结果。

## Current Problems

1. 站点外壳把品牌、工具、知识和法律/隐私页面都压缩在相同的卡片样式中，首屏缺少稳定的品牌版式节奏。
2. `nav` 在窄屏变成可横向滚动的一排链接，缺少真正的移动菜单、`aria-expanded`、Escape 关闭和焦点回收。
3. `/hexagrams` 只有顺序列表式网格，没有搜索、编号/上下卦筛选，也没有把“8 个上卦 × 8 个下卦”的结构变成可探索的信息架构。
4. 起卦流程有 `isCasting` 保护，但视觉上只有“已生成/未生成”两类，用户看不到当前处于准备、投掷、落定还是完成锁定阶段。
5. 起卦阶段的 6 个线位是进度条，结果页才显示真正六爻；起爻形成的方向、动爻标记和完成过渡可以更连贯。
6. 页面中使用大量通用圆角卡片和 pill 按钮，部分文本和边界 token 仍需统一为语义 token，减少“模板化 dashboard”感。
7. 可访问性基础较好，但移动导航、目录筛选、动态状态播报和跳转后的焦点定位还没有形成完整模式。

## Current Strengths

- 核心算法、随机源、会话格式和内容边界已由共享包、Zod 和现有测试保护；不需要也不应在 UI 重构中复制算法。
- 生产样式已经是深墨绿基线，具备太极、云气、卦象和铜色元素，适合收敛而非推倒重来。
- `prefers-reduced-motion` 已有全局降级，GSAP 只用于氛围和起卦反馈，未接入 Three.js。
- 首页、起卦、结果、卦目录、卦详情、方法、知识和隐私/条款/风险页面均有清晰的真实路由。
- skip link、focus-visible、语义标题、Axe/Playwright 和 390px 流程已有基础门禁。

## Page-by-page Audit

### 首页

- **主要任务**：理解产品、确认隐私、开始匿名起卦或探索六十四卦。
- **问题**：Hero 视觉已经有品牌标记，但信息全在一个大卡片内；“为什么可信”与“下一步”不够分层。
- **方案**：保留单一视觉中心，增加编辑式导语、卦爻 divider 和三项证据摘要；CTA 一主一次，隐私说明使用低权重但可读的 meta 行。
- **Motion**：太极慢旋、云气、卦爻呼吸；入场只做 opacity/translate，支持 reduced motion。

### 起卦

- **主要任务**：写下可选问题，连续完成六次起爻，锁定结构结果。
- **问题**：铜钱反馈和进度已有，但状态文字没有区分“已算出真实结果”和“正在展示动画”；用户无法快速理解下方爻位的形成方向。
- **方案**：加入明确状态机标签、六格 progress、铜钱投掷区、垂直六爻构建区；真实 `castNextLine` 结果先写入会话，再展示动画。
- **Motion**：三枚铜钱 2D 翻转/落定，最新爻线从下向上进入，完成后短暂 `completed` 状态再允许锁定。

### 结果

- **主要任务**：看懂本卦/变卦/动爻，复核原始铜钱并导出。
- **问题**：结果、原始记录、引用、释义和功能边界的优先级相近；移动端较长。
- **方案**：首屏先给结果摘要和卦象结构，再提供“原始记录/导出/授权内容/未启用功能”分层，保留全部审计信息。
- **Motion**：结果页只做一次克制的构形入场，不自动滚动、不延迟可操作控件。

### 六十四卦目录

- **主要任务**：按编号或上下卦探索卦象并进入详情。
- **问题**：当前为 64 个普通链接网格，没有搜索、筛选和 8×8 语义。
- **方案**：增加可访问搜索框、上下卦筛选和 8×8 组合矩阵；结果 card 只突出符号、序号、卦名和上下卦，不做 SaaS 卡片堆叠。
- **Motion**：筛选结果使用短 opacity/transform，避免布局跳动；键盘焦点始终保留。

### 卦详情

- **主要任务**：确认卦象、上下卦、编号和已授权卦辞。
- **方案**：增加“返回目录”路径、卦象结构图、来源/版本 disclosure；不增加未经核验的爻辞或解释。

### 方法与证据

- **主要任务**：理解三币算法、顺序、内容状态和启用条件。
- **问题**：现有 timeline 可用但像长文档。
- **方案**：以可视化流程节点表达“三币 → 爻值 → 六次 → 本卦 → 动爻 → 变卦”，再用状态层说明已发布/未发布。

### 知识、隐私、条款、风险

- **方案**：统一页头、章节锚点和 status/notice 组件；重点内容用语义状态而非装饰色。任何账号、云记录、AI、AR、社区、商城仍只保留未来模块边界，不在导航中伪造入口。

## Accessibility Audit

- 已有 skip link、focus-visible、语义 `main/nav/footer`、表单 label、`aria-live` 和 reduced motion。
- P0/P1 修复：移动导航 `aria-expanded/controls`、Escape 与焦点回收；目录搜索和筛选 label；起卦状态的可读播报；动效元素 `aria-hidden` 与真实值分离；所有焦点环使用语义 `--focus-ring`。
- 保持正文至少 16px、行高 1.5 以上、WCAG AA 对比度；不以 hover 作为手机唯一反馈。

## Motion Opportunities

1. 全局：太极慢旋、云气漂移、卦象呼吸；只在 no-preference 下启用。
2. 起卦：准备 → 投掷 → 落定 → 爻线成形 → 六爻完成；GSAP 仅负责多阶段序列，数据在动画前锁定。
3. 目录：筛选结果淡入，不使用布局抖动或无限滚动。
4. 结果：一次性摘要入场，导出/清除等动作不等待动画。

## P0 / P1 / P2 / P3

### P0

- 不破坏 domain、Web Crypto、sessionStorage schema、内容边界和既有质量门禁。
- 所有关键控件在 375/390px 可操作，无横向滚动，无第 7 爻、重复起爻或双击竞态。
- 移动菜单、焦点环、动态状态、reduced motion 和对比度满足可访问性门禁。

### P1

- 起卦状态机与铜钱/六爻反馈完整；六十四卦搜索、筛选、8×8 探索可用；首页/结果/方法页的信息层级明显。
- loading/error/not-found 与全局导航统一品牌体验。

### P2

- 统一墨绿/朱砂/玄黑语义 token、中文字体层级、间距和 divider；减少通用 card/pill 密度。
- 卦详情和知识/风险页面的编辑式阅读结构。

### P3

- 细节级阴影、纸张纹理感、hover 微位移、截图与视觉回归基线；在不增加大依赖的前提下继续 polish。
